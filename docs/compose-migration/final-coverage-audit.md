## Outcome and immediately actionable findings

1. **Two unassigned visible legacy dialog paths were found and reported.** NotificationHandler's accessibility/regrant prompt and paused-app prompt used real MaterialAlertDialogBuilder; ServerSelection's server-removal confirmation used fully qualified AppCompat AlertDialog.Builder. The coordinator accepted ownership. A fresh 06:05 read verifies all three construction sites now use native `WgAlertDialogBuilder` (NotificationHandler:367,388; ServerSelection:3201). Their callback behavior and dialog appearance still need current compilation/runtime checks.
2. **No additional unassigned reachable View renderer was identified.** Remaining visible legacy roots, nested adapters and real alert builders are in the active worker scopes listed below. A native root alone is not completion: Bubble/Ping were in the middle of replacing their 3 nested legacy adapters during this census.
3. **The existing `screen-parity-ledger.json` is not exhaustive or a valid screen count.** It has 137 rows, including 25 test source files and 2 non-screen helpers, but omits HomeScreenActivity, NotificationHandlerActivity, TestDialogActivity, SponsorFragment and SponsorSuccessFragment. The exhaustive 115-root matrix in this report includes those entries. This audit did not edit that other ledger.
4. **No accidental original test-file deletion or wholesale test overwrite was found.** All 99 original test-source files still exist. Seven modified originals retain the same 53 total `@Test` declarations. NetworkLogs and SummaryStatistics are intentionally ignored pending isolated integration fixtures. Counts do not prove coverage equivalence or execution; the changed cases and still-stale original selectors are recorded below.
5. **Protected core is freshly unchanged at this checkpoint.** All 522 files selected by the existing protected-core rule compare byte-for-byte to the original; no changed/removed protected file was found. All existing catalog versions, plugin entries and library entries are identical, with only new aliases added. Guard limitations and independently checked gaps are documented below.

Only this independent report was written by the audit. No application source, test, other ledger or guard was edited. No Gradle, app, emulator/device, external write or live operation was run.

## Reachability and explicit boundaries

- **Home:** HomeScreenActivity retains only CoordinatorLayout + NavHost FragmentContainerView + ComposeView navigation shell. The actual 6 graph children have native roots. Root prompts/snackbar/tour bridges create Compose content. Home's data type `AppHistogramView.Entry` does not construct or render AppHistogramView.
- **DNS/firewall hosts:** DnsDetailActivity and FirewallActivity each retain a one-page ViewPager2/FragmentStateAdapter, with XML TabLayout explicitly `gone`. Pages route to native DnsSettingsFragment/FirewallSettingsFragment. Hidden host controls are an explicit exception, not remaining visible settings content.
- **DNS fragment shells:** ConfigureRethinkBasicActivity's XML is only FragmentContainerView, selecting RethinkBlocklist/RethinkList native fragments. ConfigureOtherDnsActivity selects all five native protocol fragments; SmartDnsListActivity selects native SmartDnsListFragment. Their `dnsFragmentHost` is a programmatic LinearLayout holding a Compose header and FragmentContainerView, not a legacy wrapped screen.
- **Dynamic FragmentHost:** Current callers select RethinkPlusDashboard, ServerSelection, source-set-selected RethinkPlus, RethinkPlusManagePurchase and Sponsor. Sponsor replaces the same container with SponsorSuccess. Each class remains accounted in the matrix. A generic class-name host must not be counted native merely because one caller is native.
- **NetworkLogs:** Native tabs/pager use official AndroidFragment at NetworkLogsActivity:133. Concrete pages are ConnectionTracker, DnsLog, RethinkLog and WgNwStats, all native roots. Context-dependent page count, initial query, fragment state and maxLifecycle must be verified independently of rendering coverage.
- **Framework Dialog windows:** GenericHop, WgAddPeer, WgSsid, RpnSsid and CustomLanIp delegate to `Dialog.setWgContent`; WgHop/RpnProxyHop inherit GenericHop. WgAlertDialogBuilder creates an ordinary window with Compose content. Its import alias `as MaterialAlertDialogBuilder` is not a real Material View dialog. RPN reset progress is likewise native content inside a Dialog. Existing lifecycle/window dismissal/cancel/width contracts remain acceptance work.
- **Notification trampoline:** The two user prompts now use native WgAlertDialogBuilder. The Activity still inflates Android's sample `activity_list_item`, immediately sets decor alpha to zero, and shows no Activity content (NotificationHandler:96–97). This is an explicit invisible-host exception; it must never become visible via an alpha/lifecycle regression. It is distinct from its now-native visible dialogs.
- **Platform/library boundaries:** Permission/biometric/SAF flows, external intents, billing UI, system toasts/notifications, bubble windows and system bars stay external. WireGuard's ScanContract and JourneyApps CaptureActivity are explicitly library-owned camera/scanner UI. No actual permission, scanner, account, payment or VPN flow was exercised.
- **Empty/dormant cases:** Alerts is intentionally blank because the original alert functionality was commented. AlertAdapter is wholly commented original code. TestDialogActivity is a deliberately empty non-exported test host. RethinkListBottomSheet and RpnProxyHopDialog had no production opener in the original and still have none. CustomIp/CustomDomainFragment remain compatibility implementations while CustomRulesActivity renders native RulesPage directly.
- **Retirement:** RethinkLogBottomSheet was unused originally; original/current RethinkLogAdapter opens ConnTrackerBottomSheet. DnsCryptRelaysDialog's reachable relay flow now uses native DnsRelaysDialog. CustomLanIpDialog is retained and natively delegates in this reconstruction; do not repeat the lost checkpoint's claim that it was deleted.
- **Dormant renderers:** FirewallStatusSpinnerAdapter still inflates two row layouts but has no current source/resource caller. SponsorBadgeView still inflates its own layout but has no source/resource/XML instantiation. Retaining them does not demonstrate reachable legacy content; deleting them still requires reference/resource checks. Custom chart/map/badge/ocean/switch classes can remain for uninflated XML/ViewBinding compatibility. Actual NativeCanvas/Drawable drawing is not AndroidView. Before utility completion, recheck Ping's old signature layout/adapter links; a legacy class's existence or a new root alone does not establish the nested result.
